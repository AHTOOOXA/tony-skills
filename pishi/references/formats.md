# Форматы по задачам

Скелеты — не шаблоны для заполнения, а порядок вопросов читателя. Пустой раздел
не пишется. Длины — ориентиры; «коротко» от пользователя их перебивает. Если у
команды есть свой принятый формат (скилл FYI, конвенция PR) — он главнее.

## Сообщение коллеге в мессенджере (баг, вопрос, статус)

До 150 слов. Без приветствия, если переписывались сегодня.

```
<что ломается, для кого, с id или ссылкой>
<причина в одном-двух предложениях>
<что предлагаю / что уже сделал>
<что нужно от тебя — вопрос или действие, со сроком если есть>
```

Пример скелета: «На объектах U-161 и U-160 гости не видят код доступа — он лежит
в „Коде от подъезда“, а кабинет читает „Код доступа“. Коды рабочие, можно отдать
гостям в переписке прямо сейчас. Карточки поправлю сегодня. Нужно от тебя:
скажи операционке, куда класть код, — черновик ниже.»

## Статус / итоги для руководителя

Один экран на тему. Несколько тем — несколько сообщений или разделы с заголовком
в одну строку. Только наши числа, по отчётам.

```
<тема> (<период>)

СДЕЛАЛИ
• <факт с числом, ссылка на PR/задачу>

ПОПРОБОВАЛИ
• <что, когда включили/выключили, что показало>

УПЁРЛИСЬ
• <препятствие и причина, одной строкой каждое>

РЕШЕНИЕ <дата>
• <вариант, цена, что закрывает>

Нужно от вас:
• <согласовать X / дать доступ Y / ответить на Z>
```

Заголовки капсом и маркеры — один из рабочих вариантов; если команда привыкла к
другому виду, повторяй его.

## Тикет в трекере (Jira, Yandex Tracker, Linear)

```
Заголовок: <глагол + объект + где>  («Показывать код электронного замка в кабинете гостя»)

Что не так: <симптом для пользователя, с id примера>
Где: <страница/экран, ссылка>
Шаги: 1. … 2. … 3. …
Ожидаемо: …
Фактически: …
Причина (если известна): …
Ссылки: PR, Sentry, связанные задачи
```

Приоритет и исполнитель — полями трекера, не текстом. Без «Уважаемые коллеги»
и без «Прошу рассмотреть».

## PR body на русском

Конвенция репозитория, если она есть; иначе:

```
## Что
<одно-два предложения: что меняется для пользователя или системы>

## Зачем
<проблема с числом или задачей>

## Как
<решение по пунктам, только то, что ревьюеру нужно понять; без пересказа дифа>

## Как проверить
<шаги или команда>

## Риски / что не сделано
<миграция? фича-флаг? что уедет отдельным PR>
```

Заголовок PR — тот же глагол + объект. Скрипты, миграции, флаги — назвать явно.

## FYI команде (не-разработчикам)

Форма: заголовок «Обновили/Добавили/Починили <что> (<ссылка>)» → «Коротко, что
изменилось:» → пункты «что теперь видит/делает человек» → «Нужно от вас:» →
закрывающая строка «где смотреть». Ни файлов, ни хешей, ни «отрефакторили».
Изменение без видимого эффекта — не упоминается.

## Инструкция операционке / хостам

```
коротко: <одна строка — что делать не так, как сейчас>

сначала срочное
  <id>  <ссылка>  <что именно и до когда>

где правильное поле
  <карточка → блок → поле в «ёлочках» — и что оно значит>

что поправить
  <id>  <ссылка>  <что стоит сейчас → что должно стоять; если не знаю — вопрос>

ограничения
  <поле числовое / буквы нельзя / решётку не ставить — кабинет подставит>

что уже сделано с нашей стороны
  <одна-две строки, без внутренностей>
```

Названия полей и кнопок — как в интерфейсе. Пример «неправильно → правильно» с
реальным id обязателен: абстрактную инструкцию сделают наоборот.

## Объяснение («объясни по-русски», «в чём баг»)

3–5 абзацев, по одной мысли. Без заголовков и списков, если пунктов не больше
трёх.

```
<конкретный случай из нашей системы: объект/бронь/запрос с id — что видит человек>
<механизм: почему так происходит, шаг за шагом, кто что делает>
<последствия: кого задевает, сколько (число из логов), что будет, если не чинить>
<что предлагаю: одно решение, почему оно, что нужно решить пользователю>
```

Переспросили «ещё раз» — смени пример, не повторяй формулировки.

## Хендофф (передать работу себе-завтрашнему или другому агенту)

```
# Handoff: <ветка / задача> — <дата>

Что это за работа и зачем (2–3 предложения, с задачей)
Где мы сейчас: сделано / в процессе / не начато — по пунктам с файлами и коммитами
Что дальше — первые три шага, конкретно
Грабли — что уже пробовали и почему не сработало
Как проверить — команды, URL, чем сравнивать
Открытые вопросы — кому задать
```

Хендофф читает тот, у кого нет твоего контекста: каждая ссылка, путь и id —
явно. Никаких «как обсуждали».

## Стендап-бриф для созвона (.txt)

До 120 слов. Три блока: `сделал с прошлого раза` · `сейчас` · `нужно решить /
блокеры`. Пункты — глагол + объект + число или ссылка. Никаких процессов
(«исследовал», «изучал»), только результаты и вопросы.

## Просьба к руководителю (созвон, бюджет, доступы)

```
<что прошу — одной строкой>
<зачем — одна причина с числом>
<что нужно от тебя — список: решение / деньги (сумма) / доступ (какой) / срок>
<когда удобно — два слота>
```

## Письмо рекрутеру / отклик

Если у пользователя есть свой гайд по голосу писем — он главнее целиком. Общие
принципы: отвечать требованиям вакансии пункт в пункт своими фактами;
«прицельно» — видно, что письмо в эту компанию, а не рассылка; вместо оценок
себя — результат с числом или ссылкой; не совпадаешь с пунктом — не пиши о нём
и не извиняйся; место жительства — как факт, не как «переезжаю».

## Issue в чужой репозиторий (по-русски)

```
<Заголовок: симптом глаголом>

Что происходит: <шаги, что видит пользователь, ссылка/скрин>
Ожидалось: …
Где в коде (если нашёл): <файл:строка>, одно предложение о причине
Как бы починил: <идея в одном абзаце — без кода, если это не твой проект>
```

## Инструкция родным (VPN, звонки, приложение)

Одна задача — одно сообщение. Шаги пронумерованы, каждый — одно действие с
названием кнопки в «ёлочках». Что увидишь после каждого шага. Что делать, если
не сработало, — одна строка с «напиши мне». Без терминов: не «профиль
конфигурации», а «ссылка, которую я пришлю».

## Подпись к рилсу / пост

Первая строка — то, ради чего смотреть; факт вместо оценки («за 3 месяца −8 кг»,
не «невероятный результат»); один пост — одна мысль; призыв к действию
конкретный и один.
